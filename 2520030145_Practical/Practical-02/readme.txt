This C program demonstrates file copying using the Linux system calls open(), read(), write(), and close(). First, the source file is opened using open() in read-only mode, and a file descriptor is returned by the operating system. The destination file is then opened in write mode and created if it does not already exist. The read() system call reads the contents of the source file into a buffer, and write() transfers the data from the buffer to the destination file.
During the execution of these system calls, control moves between user space and kernel space. The C program normally executes in user space, but operations such as opening, reading, writing, and closing files require services from the Linux kernel. When a system call is made, control is transferred to kernel space, where the kernel performs the requested file operation and then returns the result to the user-space program. Thus, system calls provide an interface between the user program and the operating system kernel.
The strace utility was used to observe the system calls generated by the cat command. When cat exec3.txt was executed, strace displayed several system calls involved in starting the program and reading the file. Important calls observed included execve(), openat(), read(), write(), close(), and exit_group().
The openat() system call was used to open the specified file, while read() was used to obtain its contents. The write() system call then displayed the contents on the terminal through standard output. After reaching the end of the file, read() returned zero, indicating the end of the file, and close() released the file descriptor. Finally, exit_group() indicated the termination of the cat process.
From the experiment, it was observed that commands and programs running in Linux depend on system calls to request services from the kernel. The strace output helped in understanding the sequence of operations performed by cat and showed how user-level programs interact with the Linux kernel for file-related operations.
